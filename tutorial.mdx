# Extract structured data with Pydantic models

This tutorial teaches you how Instructor turns Pydantic models into reliable LLM extractions. You'll start with a flat model, add nested types, layer in validation, watch retries kick in when the model gets something wrong, and finish with streaming partial results.

The example throughout is extracting structured information about a research paper from a free-text abstract. By the end you'll understand why Instructor exists and when to reach for each of its features.

## Prerequisites

- Completed [Getting Started](/getting-started)
- Familiarity with Pydantic models (validators, nested types)
- An OpenAI API key set as `OPENAI_API_KEY`

## What we're building

A function that takes the abstract of a research paper and returns a structured object containing the title, authors, publication year, and a list of key findings. By the end it will also validate the year, retry on bad output, and stream partial results as the model generates them.

## Step 1: Start with a flat model

<Steps>
  <Step title="Define the model">
    ```python
    from pydantic import BaseModel

    class Paper(BaseModel):
        title: str
        authors: list[str]
        year: int
    ```
  </Step>
  <Step title="Run a basic extraction">
    ```python
    import instructor

    client = instructor.from_provider("openai/gpt-4.1-mini")

    abstract = """
    'Attention Is All You Need', published in 2017 by Vaswani, Shazeer, Parmar,
    Uszkoreit, Jones, Gomez, Kaiser, and Polosukhin, introduced the Transformer
    architecture for sequence transduction tasks.
    """

    paper = client.create(
        response_model=Paper,
        messages=[{"role": "user", "content": f"Extract paper metadata from: {abstract}"}],
    )

    print(paper)
    ```
  </Step>
  <Step title="Verify the output">
    ```
    title='Attention Is All You Need' authors=['Vaswani', 'Shazeer', 'Parmar', 'Uszkoreit', 'Jones', 'Gomez', 'Kaiser', 'Polosukhin'] year=2017
    ```
  </Step>
</Steps>

The model returned a fully validated `Paper` object. If it had returned `year: "2017"` as a string, Pydantic would have coerced it. If it had returned something genuinely wrong (`year: "seventeen"`), Pydantic would have raised `ValidationError` and Instructor would have retried.

## Step 2: Add nested models

Real extractions need nesting. Let's split each author into a name plus an affiliation, and add a list of key findings as a separate model.

```python
class Author(BaseModel):
    name: str
    affiliation: str | None = None

class Finding(BaseModel):
    claim: str
    evidence: str

class Paper(BaseModel):
    title: str
    authors: list[Author]
    year: int
    findings: list[Finding]
```

Instructor handles arbitrarily nested Pydantic models without extra configuration. The schema is generated recursively and the response is parsed into the full object tree.

```python
abstract = """
'Attention Is All You Need' (2017) introduced the Transformer architecture.
Authors from Google Brain (Vaswani, Shazeer, Parmar) and Google Research
(Uszkoreit, Jones) showed that attention mechanisms alone, without recurrence,
achieve state-of-the-art results on translation tasks. The model trained
3.5x faster than the best previous architecture.
"""

paper = client.create(
    response_model=Paper,
    messages=[{"role": "user", "content": f"Extract paper metadata from: {abstract}"}],
)

for author in paper.authors:
    print(f"{author.name} ({author.affiliation})")
```

**Expected output:**

```
Vaswani (Google Brain)
Shazeer (Google Brain)
Parmar (Google Brain)
Uszkoreit (Google Research)
Jones (Google Research)
```

## Step 3: Add validation

Pydantic validators run on every extraction. Use them to enforce real-world constraints the LLM might violate.

```python
from pydantic import BaseModel, Field, field_validator

class Paper(BaseModel):
    title: str = Field(..., min_length=1)
    authors: list[Author] = Field(..., min_length=1)
    year: int = Field(..., ge=1900, le=2030)
    findings: list[Finding]

    @field_validator("year")
    @classmethod
    def validate_reasonable_year(cls, v: int) -> int:
        if v > 2026:
            raise ValueError("Year cannot be in the future")
        return v
```

If the LLM returns `year: 1850` or `year: 2099`, Pydantic raises `ValidationError`. Instructor catches it and retries with the error message included in the next prompt, so the model can correct itself.

<Tip>
Field constraints (`ge`, `le`, `min_length`) are passed to the LLM as part of the JSON schema. The model sees them upfront and is more likely to produce valid output on the first try. Custom validators only fire after generation and only catch what slipped through.
</Tip>

## Step 4: Watch retries in action

Set `max_retries` to control how many times Instructor will reask the model on validation failures.

```python
from instructor.exceptions import InstructorRetryException

try:
    paper = client.create(
        response_model=Paper,
        max_retries=3,
        messages=[{"role": "user", "content": "Extract a paper from: nothing useful here"}],
    )
except InstructorRetryException as e:
    print(f"Gave up after {e.n_attempts} attempts")
    print(f"Last error: {e.last_completion}")
```

When the input has no extractable paper, every retry fails and `InstructorRetryException` fires after the third attempt. The exception includes the number of attempts and the last completion so you can debug.

<Warning>
`max_retries` defaults to 0. Without explicitly setting it, Instructor raises on the first validation failure. For anything production-facing, set this to at least 2.
</Warning>

## Step 5: Stream partial results

For long extractions, streaming partial results gives the user something to see while the model works. Use `create_partial`:

```python
stream = client.create_partial(
    response_model=Paper,
    messages=[{"role": "user", "content": f"Extract paper metadata from: {abstract}"}],
)

for partial in stream:
    print(partial)
```

Each iteration yields a `Paper` instance with whatever fields the model has produced so far. Fields not yet generated are `None`.

```
title='Attention' authors=[] year=None findings=[]
title='Attention Is All You Need' authors=[] year=None findings=[]
title='Attention Is All You Need' authors=[Author(name='Vaswani', affiliation=None)] year=None findings=[]
title='Attention Is All You Need' authors=[Author(name='Vaswani', affiliation='Google Brain')] year=2017 findings=[]
...
```

`create_partial` doesn't support `max_retries`. Validation only runs on the final complete object. If you need both streaming and retries, run `create` first to validate, then call `create_partial` for the user-facing stream.

## What you learned

You can now define flat or nested Pydantic models, pass them as `response_model` to Instructor, use Field constraints to guide the model, write custom validators for constraints that don't fit Field syntax, configure retries with `max_retries`, and stream partial results with `create_partial`.
